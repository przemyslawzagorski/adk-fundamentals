    Katalog funkcji systemu¶

    Referencja wszystkich kluczowych funkcji platformy ADK Fundamentals — nie tylko AuditOps. Każdy wpis: jeden akapit "co/po co", przykład kodu i wskaźnik do źródła.

    🟣 Concierge Web (module_23)¶

    FastAPI + React UI eksponujący każde narzędzie systemu jako klikalny formularz: SSE progress, telemetria, dashboard kosztów.

    Po co: Koniec żonglowania N skryptami CLI. Jedna karta przeglądarki = cała platforma.

    # adk_training/module_23_auggie_integration/web/app.py
from fastapi import FastAPI
from .tools import TOOL_REGISTRY

app = FastAPI(title="Auggie Concierge")

@app.get("/api/tools")
def list_tools():
    return [{"id": t.id, "schema": t.schema} for t in TOOL_REGISTRY]

    UI: - http://localhost:5173 — React dev server (proxy /api na backend) - http://localhost:8770/docs — auto-Swagger

    Wypróbuj: 

    .\start_all.ps1

    🔵 ACP Pool — sesje persystentne Auggie (module_23)¶

    Subprocess Auggie startuje ~2-3 s. ACP utrzymuje sesję, kolejne wywołania zajmują <500 ms.

    # Włącz przez env
$env:AUGGIE_USE_ACP="true"

    Zysk: 5× przyspieszenie na seriach krótkich callów. Źródło: adk_training/module_23_auggie_integration/acp_pool.py

    🟡 LRU Cache (module_23)¶

    Eliminuje powtarzalne wywołania Auggie. Klucz = SHA256(prompt + model + return_type + extra_cli).

    GET /api/cache/stats
{ "hits": 142, "misses": 38, "saved_seconds": 410.5, "hit_ratio": 0.79 }

    Co pomijamy: zapytania z success_criteria (każda runda weryfikacji musi być świeża), functions=[...] (niedeterministyczne), TTL 1 h. Źródło: adk_training/module_23_auggie_integration/caching.py

    🟠 Resilience — retry + circuit breaker (module_23)¶

    # Retry: 1 s, 2 s, 4 s, 8 s z jitter
# Breaker: 5 failów w 60 s → open na 120 s

@with_retry(max_attempts=4)
@with_breaker(name="auggie", threshold=5, timeout=120)
def call_auggie(prompt: str) -> str: ...

    Źródło: adk_training/module_23_auggie_integration/resilience.py

    🔵 Code Analyst (module_13)¶

    Czyta tickety Jira, indeksuje lokalne repo z embeddingami, proponuje łatki lub otwiera MR-y w GitLabie.

    POST /api/tools/run
{ "tool_id": "code_analyst", "inputs": { "ticket": "PROJ-1234", "create_mr": true } }

    Okazja na skille: progressive-disclosure mógłby tu wejść — jeden skill na typ refactoringu (extract-method, bump-dep, sql-migration). Patrz Wzorce platformy.

    🟡 Spec Generator (module_22)¶

    spec = generate_openapi_spec(prompt="Library API: books, members, loans")

    Okazja na skille: jeden SKILL.md na styl spec — REST, GraphQL, gRPC, AsyncAPI. Recon = parse istniejących endpointów.

    🟣 Gmail Integration (module_15)¶

    Wysyła draft, nigdy nie auto-sendsuje. Ten sam dry-run + consent pattern co AuditOps safety.py.

    draft = gmail.create_draft(to=..., subject=..., body=...)
# Operator klika "Wyślij" w Gmailu — nie agent

    🟠 Database agents (module_09)¶

    PostgreSQL i SQLite. module_09_database_postgres dodaje introspekcję schematu (\d+ table) przed syntezą zapytania — ten sam pattern tani-probe → drogi-plan co AuditOps recon.

    🔴 ADK Tester (module_21)¶

    Auto-generuje testy pytest dla agentów ADK. Mógłby wciągnąć pattern wiki audit-history: historia testów per-agent, regresje z poprzednich runów.

    Podsumowanie kosztów — co kosztuje ile¶

    Funkcja Pamięć CPU Tokeny / call Latency
    Concierge UI 60 MB minimum 0 <50 ms
    Auggie subprocess 250 MB wysokie (boot) ~3 k 2-3 s cold
    Auggie ACP 250 MB shared niskie ~3 k <500 ms
    Cache hit (LRU) minimum minimum 0 <5 ms
    AuditOps full run 350 MB średnie 20-50 k 30-90 s
    Skills L1 manifest minimum minimum ~200 <10 ms
